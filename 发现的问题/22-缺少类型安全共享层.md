# 22. 缺少类型安全共享层

> **严重度**：🟡 关注
> **涉及文件**：前后端 API 接口（如 `api/stats.ts` vs 后端路由）
> **类型**：架构
> **状态**：✅ 已解决

## 问题描述

前后端使用独立的类型定义，没有共享类型层：

```js
// 后端 (JavaScript) — 无类型系统
// server/routes/stats.js
res.json({
  visitors: stats.visitors.size,
  totalSessions: stats.totalSessions,
  activeSessions,
  agentDistribution: {...}
})
```

```tsx
// 前端 (TypeScript) — 手动定义接口
// client/src/api/stats.ts
export interface BasicStats {
  visitors: number
  totalSessions: number
  activeSessions: number
  agentDistribution: Record<string, number>
}
```

### 风险

- 后端改了返回结构但前端忘记更新类型 → 编译不报错，运行时为 `undefined`
- 前端定义的接口和实际返回的数据可能不一致
- 重复劳动：每个 API 的类型定义需要在两端各写一次

## 改进方向

1. 建立 `packages/types/` 共享类型包（monorepo 结构）
2. 或使用 OpenAPI 规范定义 API，通过 `openapi-typescript` 自动生成类型
3. 或后端迁移到 TypeScript，导出类型供前端引用
