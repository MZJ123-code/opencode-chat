# 01. IP 作为用户身份标识不可靠

> **严重度**：🔴 严重
> **涉及文件**：`server/middleware/clientIP.js`、`server/services/userService.js`、`server/services/sessionService.js`
> **类型**：架构

## 问题描述

整个系统的用户识别完全依赖 `req.clientIP`：

```
server/middleware/clientIP.js:11
  req.clientIP = getClientIP(req)

server/services/userService.js
  getClientIP() 从 x-forwarded-for → x-real-ip → socket.remoteAddress 提取
```

这是一个根本性的设计缺陷：

1. **NAT 环境不可用**：公司内网多人共享同一公网 IP（如 100.64.x.x 或 10.x.x.x），A 用户能看到 B 用户的会话，数据完全交叉
2. **移动设备不可用**：手机切换 WiFi/4G 导致 IP 变化，之前的会话"丢失"
3. **IP 可伪造**：`x-forwarded-for` 请求头可被客户端任意设置，无任何签名验证
4. **无法用于生产**：无认证、无 session token、无 API key，不能对外提供服务

## 具体风险场景

- 团队 5 人通过公司 NAT 访问 → 共享同一公网 IP → 每人看到所有会话
- 用户在咖啡店用手机访问 → IP 变化 → 历史会话丢失
- 恶意用户设置 `x-forwarded-for: 192.168.1.100` → 可访问该 IP 用户的会话

## 改进方向

| 方案 | 复杂度 | 效果 |
|------|--------|------|
| localStorage UUID + cookie | 低 | 临时方案，基本可用 |
| GitHub OAuth 登录 | 中 | 可靠的用户身份 |
| Session Token + 签名 | 中 | 自建认证系统 |
| 企业 SSO (OIDC/SAML) | 高 | 企业级身份管理 |
