# 13. 日志 I/O 性能问题

> **严重度**：🟡 关注
> **涉及文件**：`server/logger/index.js`
> **类型**：运维

## 问题描述

日志模块每次写入都进行两次 I/O 操作：

```js
// logger/index.js:89-93
function append(line, level) {
  console.log(...)                       // 控制台输出
  enqueue(() => fsp.appendFile(...)      // 异步文件追加
    .then(() => debouncedArchive())       // 每次追加后检查文件大小
  )
}
```

### 问题

1. **每次日志触发 fs.stat**：`debouncedArchive()` 虽 debounce 了 5 秒，但仍会定期调用 `fsp.stat` 检查文件大小
2. **safeStringify 每次 JSON.parse**：

```js
// logger/index.js:61-68
function safeStringify(data) {
  if (typeof data !== "object") return String(data)
  try { return JSON.stringify(data) } catch { return String(data) }
  // 高频场景下，JSON.stringify 大对象消耗 CPU
}
```

3. **高并发场景**：SSE 大量事件日志、多个用户同时操作时，日志 I/O 可能成为瓶颈

## 改进方向

1. 引入 pino 或 winston 等成熟日志库，支持日志级别过滤
2. 开发环境使用 console 即可，生产环境才写入文件
3. 缓冲批量写入：每 100ms 合并一次写入，而非每条日志单独写
