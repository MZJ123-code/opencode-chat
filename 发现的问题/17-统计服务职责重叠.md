# 17. statsService 和 analyticsService 职责重叠

> **严重度**：🟡 关注
> **涉及文件**：`server/services/statsService.js`、`server/services/analyticsService.js`
> **类型**：后端
> **状态**：✅ 已解决

## 问题描述

两个服务模块记录相似的统计数据，但存储方式不同：

| 维度 | statsService | analyticsService |
|------|-------------|-----------------|
| 存储方式 | 内存 Map + `_stats.json` | SQLite (bun:sqlite) |
| totalQuestions | ✅ | ✅ |
| satisfied | ✅ | ✅ |
| unsatisfied | ✅ | ✅ |
| visitors | ✅ | ✅ |
| 记录访问 | ❌ | ✅ (page_visits) |
| 提问明细 | ❌ | ✅ (questions) |
| 反馈明细 | ❌ | ✅ (feedback) |

### 问题

1. **数据冗余**：`totalQuestions` 和 `satisfied`/`unsatisfied` 在两个系统中都有记录
2. **不一致风险**：内存中的统计和 SQLite 中的计数可能不同步
3. **复杂度**：需要理解两套系统才能修改统计逻辑
4. **持久化不一致**：内存统计靠 10 秒 debounce 写 JSON，SQLite 实时写入，重启后两者不一致

## 改进方向

统一到 SQLite 单一数据源，去掉 `_stats.json` 和内存中的 `stats` 对象。`getStats()` 改为从 SQLite 聚合查询。
