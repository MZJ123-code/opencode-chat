# 07. SSE 缓冲机制不可靠

> **严重度**：🟠 中等
> **涉及文件**：`server/services/eventBuffer.js`
> **类型**：后端

## 问题描述

SSE 重连后的增量回放机制存在两个限制：

```js
// eventBuffer.js
const MAX_BUFFER = 200       // 每 IP 最多 200 条
const BUFFER_TTL = 5 * 60 * 1000  // 5 分钟空闲清理
```

### 问题

1. **容量限制**：200 条事件很快就满，高频 AI 回复场景下，老事件迅速被 `shift()` 弹出
2. **TTL 限制**：客户端断连 5 分钟以上，缓冲区被清理，重连后只能从空开始
3. **丢失不可恢复**：丢失的事件永久丢失，无法从任何地方重新获取

### 影响场景

- 用户合上笔记本 10 分钟后打开 → 缓冲区已清理 → AI 回复不完整
- 一条长回复产生 300 个 delta 事件 → 最早的 100 个在缓冲区中被覆盖
- 网络不稳定频繁重连 → 每次重连都可能丢失部分事件

## 改进方向

1. 增大 MAX_BUFFER 到 5000+
2. 延长 TTL 到 30 分钟
3. 改用 SQLite 持久化事件序列
4. 实现基于 session + sequence 的完整回放机制
