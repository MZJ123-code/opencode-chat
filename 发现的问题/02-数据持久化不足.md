# 02. 数据持久化严重不足

> **严重度**：🔴 严重
> **涉及文件**：`server/storage/store.js`、`server/services/statsService.js`、`server/storage/database.js`
> **类型**：存储

## 问题描述

系统中存在**三种存储机制**，但核心数据落在最不持久的那一层：

```
┌─────────────────────────────────────────────────────┐
│  内存 Map（无持久化）                                  │
│  sessionMeta  ← 会话元数据（重启丢失）                 │
│  ipUsers      ← 用户会话关联（重启丢失）               │
│  ipSessions   ← IP会话列表（重启丢失）                 │
├─────────────────────────────────────────────────────┤
│  JSON 文件（部分持久化）                                │
│  logs/_stats.json ← 统计数字（有恢复但字段不一致）      │
├─────────────────────────────────────────────────────┤
│  SQLite（持久化）                                      │
│  logs/analytics.db ← page_visits / questions / feedback│
└─────────────────────────────────────────────────────┘
```

### 具体问题

1. **会话数据全在内存**：`sessionMeta`、`ipUsers`、`ipSessions` 三个核心 Map 没有任何持久化。服务器重启后所有会话"消失"
2. **stats 恢复有 bug**：`restoreStats()` 存的是 `activeIPs`，但 JS 对象中是 `visitors` 字段，读出来赋值 `stats.visitors` 但写入的 key 不是这个

```js
// statsService.js:15
if (data.visitors) stats.visitors = new Set(data.activeIPs || [])
// 注意：JSON 里存的是 activeIPs，这里读的是 data.activeIPs
// 而下一行检查 data.visitors 但 JSON 中可能不存在这个 key
```

3. **冷启动数据丢失**：SQLite 中有 `questions` 和 `feedback` 明细数据，但缺少 `sessions` 表来恢复会话元数据

## 影响

- 服务器重启 → 所有用户看到会话列表为空
- 用户要重新创建会话
- 历史对话内容仍在 OpenCode 内存中（如果进程未重启），但前端无法访问
- 统计数据重置

## 改进方向

1. 将 `sessionMeta` 写入 SQLite，启动时自动恢复
2. 将 `ipUsers` / `ipSessions` 改为由 SQLite 查询派生
3. 统一统计源：去掉 `_stats.json`，全部改用 SQLite
4. 引入 `sessions` 表持久化会话元数据
