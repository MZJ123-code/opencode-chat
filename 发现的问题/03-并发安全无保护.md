# 03. 并发安全无保护

> **严重度**：🔴 严重
> **涉及文件**：`server/storage/store.js`、`server/services/sessionService.js`、`server/routes/events.js`
> **类型**：后端

## 问题描述

三个核心数据结构被多条代码路径同时修改，没有任何锁或事务保护：

```js
// store.js
export const ipUsers = new Map()      // IP → {sessionIds: Set}
export const ipSessions = new Map()    // IP → string[] (数组)
export const sessionMeta = new Map()   // sessionId → SessionMeta
```

### 并发修改路径

```
HTTP 路由                          SSE 事件流                         定时器
(POST /api/sessions)               (GET /api/events)                  (setInterval)
       │                                  │                               │
  createSession()                    processEvent()                 cleanupExpiredSessions()
       │                                  │                               │
       ├── sessionMeta.set(id)            ├── sessionMeta.set(id)         ├── sessionMeta.delete(id)
       ├── ipUsers.get(ip).add            ├── ipUsers.get(ip).add         ├── ipUsers.get(ip).delete
       └── ipSessions.get(ip).push        └── ipSessions.get(ip).push     └── ipSessions.get(ip).splice
```

### 具体问题

1. **双存储不一致**：`ipSessions`（数组，有序）和 `ipUsers.sessionIds`（Set，无序）存储同一个 IP 的会话列表，但两者独立维护
2. **淘汰操作无事务**：`evictOldestSession()` 先删 Set 再删数组：

```js
// sessionService.js:16-22
function evictOldestSession(ip) {
  const ids = ipSessions.get(ip)
  if (!ids || ids.size === 0) return
  const oldestId = ids.values().next().value  // 取 Set 第一个
  ids.delete(oldestId)                         // 删 Set
  ipUsers.get(ip)?.sessionIds.delete(oldestId)  // 删 另一个 Set
  sessionMeta.delete(oldestId)                  // 删 元数据
  // 如果中间抛出异常，数组和 Set 状态不一致
}
```

3. **异步操作间无保护**：`await` 点让出执行权后，其他请求可能修改同一数据

## 影响

- 数据不一致：Set 中有但数组中没有，或反之
- 会话重复显示或丢失
- 统计数字不准确

## 改进方向

1. 统一数据源：去掉冗余的 `ipSessions` 数组，仅保留 Set
2. 将对 Map 的写操作集中到单一模块，用队列串行化
3. 引入 SQLite 事务保障一致性
