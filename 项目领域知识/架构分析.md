## 请求流程

### 同步聊天（已废弃）

```
POST /api/chat  { sessionId, message, agent }
  → 已删除。所有聊天统一使用异步 SSE 模式。
```

### 异步聊天（唯一聊天方式）

```
POST /api/chat/async  { sessionId, message, agent }
  → 同上校验 + 记录
  → client.session.promptAsync() (不等待)
  → 立即返回 { ok: true }

SSE /api/events (持续连接)
  → 订阅所有 Agent 目录的事件流
  → message.part.updated → 实时推送 Part 更新
  → message.part.delta → 文本增量
  → session.next.tool.* → 工具调用状态
  → session.next.reasoning.* → 推理过程
  → session.status → 会话状态变更
```

### 权限弹窗流程

```
Agent 需要执行敏感操作
  → OpenCode 发送 permission.asked / question.asked 事件
  → SSE 转发到前端
  → PermissionDialog 弹窗
  → 用户操作 → POST /api/permission/respond 或 /api/permission/question/reply
  → Express 调用 SDK 的 permission 响应接口
```

### 并发数据修改路径（已知风险点）

```
HTTP 路由                    SSE 事件流                    定时器
(POST /api/sessions)         (GET /api/events)              (setInterval)
       │                           │                            │
       │  createSession()          │  processEvent()            │ cleanupExpiredSessions()
       │                           │                            │
       ├── sessionMeta.set(id)     ├── sessionMeta.set(id)      ├── sessionMeta.delete(id)
       ├── userSessions.get.get(id)├── userSessions.get.add     ├── userSessions.get.delete
       └── [SQLite write]          └── [no SQLite write]        └── [SQLite delete]
                ▲                           ▲                           ▲
                └────────── 三者无锁并发修改同一 Map ──────────────────┘
```

**已知风险**：
1. **recordMessage 竞态**：message_count 的读-增-写非原子操作，并发时可能丢失计数
2. **事件缓冲内存泄漏**：用户断开后 buffer 保留至 30 分钟 TTL，高并发下累积大量事件
3. **SSE 无背压处理**：`res.write()` 忽略返回值，慢客户端可能导致内存暴涨
4. **AbortController 泄漏**：subscribe 失败时 controller 未被 abort

### SSE 多流订阅模型

```js
// server/routes/events.js:165-169
const subscribeTasks = [client.event.subscribe()]  // 默认目录
for (const dir of AGENT_DIR_MAP.values()) {         // 每个独立目录
  subscribeTasks.push(client.event.subscribe({ directory: dir }))
}
const streams = await Promise.all(subscribeTasks)
// 若 3 个 Agent 有独立目录 → 4 个长连接 / 客户端
```

每个客户端连接维护 N+1 个 OpenCode 事件订阅流（N = 配置了独立目录的 Agent 数量），所有流的事件通过 `processEvent()` 合并后转发给浏览器。

### 子会话导航

```
主会话 → Agent 使用 task 工具创建子会话
  → OpenCode 发送 session.created 事件 (含 parentID)
  → SSE processEvent() 检测到子会话 → sessionMeta 注册
  → 前端 ChatContext.onSessionUpdated 处理
     → sessionMetaRef 记录 parentID
     → taskCallToChild 映射 (靠顺序匹配 unmapped.shift())
  → 用户可点击子会话导航
  → navigateToSession(sessionId) 切换
  → navigateBack() / navigateToParent() 返回
  → 导航栈存在 ref 和 state 双存储 (navigationStackRef + navigationStack)
```

### SDK 版本差距分析

本项目使用 `@opencode-ai/sdk` v1.14.29（`/v2` 导入路径），最新版 v1.17.4（约 300 个版本差距）。

| 差异项 | 本项目 (v1.14.29) | 最新版 (v1.17.4) |
|--------|-------------------|------------------|
| 导入路径 | `@opencode-ai/sdk/v2` | `@opencode-ai/sdk`（统一入口） |
| 异步提示 | `client.session.promptAsync()` | `client.session.prompt({ body: { parts, ... } })` 默认异步 |
| 事件订阅 | `client.event.subscribe({ directory? })` | `client.event.subscribe()`（路径 `/event`） |
| 结构化输出 | 不支持 | `body.format: { type: 'json_schema', schema: {...} }` |
| 会话分叉 | 不支持 | `client.session.fork({ path, body })` |
| 会话分享 | 不支持 | `client.session.share({ path })` / `unshare()` |
| Server 认证 | 无 | `OPENCODE_SERVER_PASSWORD` HTTP Basic Auth |
| API 文档 | 无 | `/doc` 端点提供 OpenAPI 3.1 Spec |

**升级风险**：`promptAsync` 在新版中已改为 `prompt()` 的默认行为（非阻塞），直接升级需要适配 API 变更。
