# OpenCode Chat — 前端优化规划

> 基于 2026-05-24 前端代码分析。按优先级分为 P0（阻塞/正确性）、P1（性能/架构）、P2（代码整洁）三级。

---

## P0 — 必须修复

### 0.1 `ChatContext` 模块级变量竞态

**问题**：`ChatContext.tsx` 中 `let renderPending = false` 和 `let bgFlushTimer` 声明在组件外部。React StrictMode 下组件会双重渲染，两个实例共享同一组变量，导致 `renderPending` 状态互相覆盖、定时器互相取消，造成 UI 更新丢失。

**方案**：将这两个变量移到 `useRef` 中：

```ts
const renderPendingRef = useRef(false)
const bgFlushTimerRef = useRef<ReturnType<typeof setTimeout>>()
```

**影响范围**：`client/src/contexts/ChatContext.tsx`

---

### 0.2 SSE 重连退避不归零

**问题**：`useEvents.ts` 中指数退避（`retryRef.current`）在连接成功接收合法事件后不重置。长时间运行的应用如果偶发断连，退避值可能累积到 30s+，后续重连等待时间越来越长，恢复响应变慢。

**方案**：在 `onopen` 或收到首个业务事件时重置 `retryRef.current = 0`：

```ts
function onOpen() {
  retryRef.current = 0
  // ...
}
```

**影响范围**：`client/src/hooks/useEvents.ts`

---

### 0.3 SSE 断连后实时消息丢失

**问题**：前端 SSE 断连期间后端推送的事件全部丢失。OpenCode SDK 无游标概念，无法回放。AI 正在回复时断连，用户必须重新发送消息。

**方案**：重连后自动发送 `GET /api/sessions/:id/messages` 拉取最新消息，与本地消息对比，补全缺失片段。

**影响范围**：`client/src/hooks/useEvents.ts`、`client/src/contexts/ChatContext.tsx`

---

### 0.4 类型安全黑洞

**问题**：`ChatContext.tsx` 中大量使用 `as unknown as Record<string, unknown>` 绕过类型系统。`getMsgInfo`、`setMsgInfo`、`injectPartToSession`、`getPartText`、`setPartText` 五个函数均无类型保障；SSE 事件处理函数接收无类型 `Record<string, unknown>` 参数。

**方案**：为消息 Part 定义精确联合类型，替换所有 `Record<string, unknown>`：

```ts
export type MessagePart =
  | { type: 'text'; text: string }
  | { type: 'reasoning'; text: string }
  | { type: 'tool_call'; callId: string; toolName: string; args: unknown }
  | { type: 'tool_result'; callId: string; output: string; isError?: boolean }
```

事件处理函数签名改为接收明确类型参数。

**影响范围**：`client/src/contexts/ChatContext.tsx`、`client/src/types/message.ts`

---

### 0.5 重复 agent 条目

**问题**：`server/config.json:63-67` 中 `"门子俊"`（agent: "explore"）与上方 `"代码探索"` 完全重复，导致前端 Agent 选择页出现两个功能完全相同的选项。

**方案**：删除多余的 agent 条目。

**影响范围**：`server/config.json:63-67`

## P1 — 建议优化

### 1.1 `ChatContext` 拆分

**问题**：773 行单一 Context 耦合了会话管理、消息存储、SSE 事件分发、导航栈、权限弹窗、输入状态等。任何状态变更都导致所有消费者重渲染。模块级变量 `renderPending` / `bgFlushTimer` 跨实例共享。

**方案**：拆为多个子 Context + 一个聚合层：

```
ChatContext (薄层，仅聚合导出)
├── SessionContext          — 会话 CRUD + 当前选中
├── MessageContext          — 消息 Map + 流式状态
├── StreamContext           — SSE 事件订阅与分发
├── NavigationContext       — 多会话导航栈
└── PermissionContext       — 权限弹窗状态
```

- 每个子 Context 只触发关注它的组件重渲染
- 每个文件从 773 行降到 ~150 行
- `renderPending` / `bgFlushTimer` 归属 StreamContext，天然隔离

**影响范围**：`client/src/contexts/`（重写）、`client/src/App.tsx`、各消费组件

**收益**：减少无关重渲染，消除模块级变量竞态。

---

### 1.2 SSE 事件解析容错

**问题**：`useEvents.ts` 对 SSE 事件数据直接解析，没有 `try/catch` 保护。如果后端发送格式异常的数据（如网络传输截断），整个 `onmessage` 处理链会抛出未捕获异常，导致 EventSource 连接被关闭。

**方案**：在事件分发入口添加 `try/catch`：

```ts
function onMessage(event: MessageEvent) {
  try {
    const data = JSON.parse(event.data)
    handlers[data.type]?.(data)
  } catch (e) {
    console.warn('[SSE] 解析事件失败:', e, event.data)
  }
}
```

**影响范围**：`client/src/hooks/useEvents.ts`

---

### 1.3 Debug 日志环境守卫

**问题**：`useEvents.ts:15` 使用 `window.__DEBUG_EVENTS__` 全局变量控制调试日志，生产构建无法被 tree-shaking 移除，且污染全局命名空间。

**方案**：替换为 `import.meta.env.DEV`：

```ts
if (import.meta.env.DEV && window.__DEBUG_EVENTS__) {
  console.log('[SSE]', eventType, data)
}
```

Vite 在 `npm run build` 时会自动将 `import.meta.env.DEV` 替换为 `false`，整段代码被 tree-shaking 移除。

**影响范围**：`client/src/hooks/useEvents.ts`

---

### 1.4 虚拟列表支持

**问题**：超长对话（>100 条消息）时所有 DOM 节点同时渲染，`MessageList.tsx` 中使用 framer-motion 为每条消息做入场动画，滚动性能下降明显。

**方案**：引入 `@tanstack/react-virtual` 实现虚拟滚动，只渲染可视区域内的消息。

```ts
const { virtualItems, totalSize } = useVirtualizer({
  count: messages.length,
  getScrollElement: () => scrollRef.current,
  estimateSize: () => 120,
})
```

**影响范围**：`client/src/components/chat/MessageList.tsx`、`package.json`（新增依赖）

**收益**：1000 条消息时 DOM 节点从 1000+ 降到 ~20。

---

### 1.5 `dangerouslySetInnerHTML` 替换

**问题**：`MessageList.tsx:65` 的 `renderThinkingPart` 使用 `dangerouslySetInnerHTML` + `escapeHtml` 组合。虽然无 XSS 风险，但性能不如 React 原生文本渲染（跳过 React 的 diff 机制，且会额外触发 `innerHTML` 解析）。

**方案**：替换为 React 原生 JSX：

```tsx
function renderThinkingPart(part: MessagePart) {
  return (
    <div key={part.id} className="thinking-part">
      {part.text}
    </div>
  )
}
```

**影响范围**：`client/src/components/chat/MessageList.tsx`

---

### 1.6 `useEffect` 依赖链

**问题**：`ChatContext.tsx:733` 的 `useEffect(() => { loadSessions() }, [loadSessions])`。`loadSessions` 虽然用 `useCallback` 包装，但其依赖 `clientIP` 来自 `client.ts` 中初始化的变量，每次渲染 `loadSessions` 都会产生新引用。

**方案**：使用 ref 保存 `loadSessions` 引用，或用 `useEffectOnce` 模式：

```ts
const loadSessionsRef = useRef(loadSessions)
loadSessionsRef.current = loadSessions

useEffect(() => {
  loadSessionsRef.current()
}, []) // 仅首次挂载执行
```

**影响范围**：`client/src/contexts/ChatContext.tsx`

---

### 1.7 SSE 连接状态可视化

**问题**：SSE 断连时前端无任何 UI 反馈，用户发送消息后长时间无响应才意识到断连。

**方案**：在 `ChatHeader` 或 `ChatInput` 上方显示连接状态指示器：

- 绿色圆点：已连接
- 黄色圆点：正在重连（显示退避倒计时）
- 红色圆点：断开（多次重试失败）

**影响范围**：`client/src/contexts/ChatContext.tsx`（暴露连接状态）、`client/src/components/chat/ChatHeader.tsx`（展示指示器）

### 2.2 `formatDate` 硬编码 locale

`client/src/utils/formatDate.ts` 只返回 `zh-CN` 格式。建议支持 locale 参数：

```ts
export function formatDate(date: Date, locale = 'zh-CN') {
  return new Intl.DateTimeFormat(locale, {
    month: 'short', day: 'numeric', hour: '2-digit', minute: '2-digit'
  }).format(date)
}
```

### 2.3 CSS Modules 冗余样式

`ToolCallBlock.module.css`（251 行）和 `MessageList.module.css`（234 行）中存在大量重复或未使用的 CSS 类。建议使用 `purgecss` 分析，或手动清理。

### 2.4 无 lint / 无测试

`AGENTS.md` 确认项目无 ESLint、无 Prettier、无测试框架。建议最小化引入：
- **ESLint** + `typescript-eslint`：捕获 `any` 和未使用变量
- **Prettier**：统一格式（现有代码风格不一致，混用单引号/双引号）
- **Vitest** + `@testing-library/react`：为 `PermissionDialog`、`MessageList` 核心组件写 smoke test

### 2.5 Theme flash 预防

当前主题在 React 挂载后读取 localStorage 再切换 `.dark`，导致页面加载时先显示亮色再切暗色（flash of wrong theme）。建议在 `index.html` 的 `<head>` 中内联脚本：

```html
<script>
  if (localStorage.getItem('opencode-theme') === 'dark' ||
      (!localStorage.getItem('opencode-theme') && window.matchMedia('(prefers-color-scheme: dark)').matches)) {
    document.documentElement.classList.add('dark')
  }
</script>
```

**影响范围**：`client/index.html`
